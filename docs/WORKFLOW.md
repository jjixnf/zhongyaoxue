# 错题、笔记和知识点审核归档工作流

**2026-10-19 用户决定：一切资料先经过助手的分析、复核和分类后，再由助手提交 GitHub；无需用户自行填写 GitHub Issues 或网页表单。** 本地记录/Issues 仅为可选途径，不是正常必需步骤。

## A. 直接在 ChatGPT 里发送（默认唯一主流程）
1. 给出截图、原题文字、自己的选项/答案和想法；零散资料也可以。
2. 助手对照教材来源，分辨错因、修正明显识别错误并标记疑点。
3. 通过 `herbIds` 和 `knowledgeIds` 关联现有知识节点；新节点需要稳定 ID。
4. 对重复题/重复笔记做合并或增加引用，不覆盖已有个人原始记录。
5. 写入 `data/questions.json`、`data/notes.json` 或 `data/knowledge.json`，记录 `createdAt` 和 `updatedAt`，并向 `data/events.json` 加入真实日期事件。
6. 创建 PR、运行校验、合并，再从网页核对显示情况。

## B. Github Issues（仅外部使用者的可选建议渠道）
1. 从 GitHub 仓库进入 **Issues → New issue**。
2. 选择「提交错题」「提交笔记/知识点」或「纠错/补充药物资料」模板。
3. 填写原始内容、相关药物名称/章节、参考来源；可粘贴截图到编辑器。
4. 提交 Issue 后先进入**待审核队列**，不会自动出现在网站里。
5. 维护者整理关联、校对、提交 PR、合并，最后在 Issue 里留下关联链接并关闭。
6. 其他同学也可提交，但没有仓库写权限者不能直接覆盖正式资料。

## C. 在网站使用“＋错题”“＋笔记”
- 当前版本写入浏览器 localStorage；可立刻在这台设备浏览、检索和日历查看。
- **这不是 GitHub 提交**。需要点击「导出我的记录」保存 JSON，之后将 JSON 发给 ChatGPT 或在 Issue 提交。
- 未来可增加受保护的登录/审核/提交队列，但不在公开静态页里嵌入 GitHub PAT。

## 资料类别和建议输入
### 错题
原题/选项，题目来源，原来选择与标准答案（不确定可空），错误原因（不确定则留空）、题目日期、药名或章节以及笔记/图片来源。
### 笔记
笔记原文、笔记性质（个人总结/记忆口诀/教材摘录/待核查）、关联药名及考点、参考来源或页码、创建日期。
### 药物资料/知识点
药名、分类章节、性味归经、功效、主治、用法用量、煎服、炮制、使用注意、配伍、辨析及原书特有考点；逐项记录出处与复核状态。暂未录入的项目留空，不能把少量摘要当作完整药物资料。

## 逐书逐药详细录入与验收
1. 确认用户所用版本及原书页面，先列出该药全部知识点；OCR/文本提取只作定位与初稿，以原书截图或 PDF 页面人工复核。原书无法访问时只补结构或标具体待核查项，不凭记忆填入教材事实。
2. 按知识事实拆分条目，用自己的结构和表达完整整理；保留药名、规范术语、具体数值、限定条件和并列考点。可以少量必要引述，不公开上传原书扫描页、全文或长篇连续原文；不因避免逐字复制而缩减知识范围。
3. 对照原书检查：主治的病证/兼症/条件；用量范围与单位、给药途径、煎服时长、先后次序和特殊处理；炮制方法及生用/炙用的功用区别；禁忌和慎用对象/条件；配伍对象、作用及适用条件；辨析的共同点、差异和适用情形。原书未载项目不自行补成教材结论。
4. 多项事实可在详情中使用 `items: [{label,text,source?,reviewStatus?}]`，节级仍保留 `text`、`source`、`reviewStatus`；有 `items` 时用 `items.map(i => i.label + '：' + i.text).join('\n')` 生成完整 `text`，兼容旧页面与对比器。条目未单列元数据时继承所在节。每项保留可追溯的书名、印刷页码与一基 PDF 页码；已复核的节/条目须有有效的 `source.pdfPage` 及 `source.verification`，后者记录 `method: "pdf-visual"`、`verifiedAt: "YYYY-MM-DD"` 和具体 `scope`。不确定字词、数值、条件或相互冲突的依据须留下具体疑点，确认前不得标为已复核。
5. 按实际范围更新复核状态：某条用法或某个字段核对完成，只更新该范围；整味药仍可保持“待逐味复核”。整味药全部原书知识点核完才可更新整体状态，不据单字段核查宣称27味或全书均已校对。
6. 网页保持功效常显，细节分条便于查阅；来源和复核状态默认作为元数据保存，通过统一出处入口追溯，不在每节重复展示“来源：……”“原书信息已摘录，表述待终审”。真实疑点应具体说明。验收时检查页面和横向对比中的用量、煎服与炮制条目均未丢失。
7. 运行数据校验和 JavaScript 语法检查，并在桌面、手机布局实际查看相关页面；提交时报告本次录入/复核的药物和字段、仍待核查内容，不用“已完善”代替具体范围。

## 来源和时间
- 教材依据优先采用用户提供的《学霸笔记—中药学》，版本不同必须标注。出处和复核信息应保存在结构化字段中，不因界面省略重复提示而删除。
- GitHub 提交日期不等于用户首次做错题或写笔记的日期，旧记录需要保留真实日期，未知就标记未知。
- 统一显示北京时间/Asia/Shanghai 的自然日。日历不自动创建复习任务。
